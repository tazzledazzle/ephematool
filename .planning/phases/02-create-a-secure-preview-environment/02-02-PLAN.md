## Phase Goal

**As an** SRE, **I want to** create a preview environment from a branch, PR or ref with one dashboard action, **so that** it comes up isolated, resource-limited and emitting telemetry, with the whole creation visible as one trace.

<objective>
Define the configuration contract every later Phase 2 plan consumes (interface-first), harden config loading (review WR-03, WR-08, part of WR-09), pre-wire the Compose api/worker environment and dev-only secrets so later plans do not edit `deploy/compose.yaml` concurrently, and resolve the conventions-literal grep trap with one generated env file.

Conventions decision (the trap in `scripts/verify.d/conventions.sh`): extend `tools/genconventions` to also emit `environments/conventions.gen.env`. Consumers never hand-write `ephematool.io/` or `ephematool.env.`: the collector reads `${env:EPHEMATOOL_ATTR_ENV_ID}` (plan 02-09, compose `env_file`), kind manifests carry placeholders substituted by `tools/kind.sh` (plan 02-13), `provision.sh` and Helm receive keys as variables (plan 02-13). The gate is widened, not weakened: `.gen.` files stay exempt because they are drift-checked by `//:check_gen`.

Output: config fields + tests, `.env.example`, compose pre-wiring, `ensure_secrets` in stack.sh, generator `-env-out`, `//environments:gen`, widened gate.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Environment variables → API/worker process | Misconfiguration can silently disable security controls |
| Developer disk → containers | Secret files are mounted into api and worker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Information disclosure | Session cookie over http when deployed with https PUBLIC_BASE_URL (WR-03) | mitigate | config.validate rejects https PUBLIC_BASE_URL or PREVIEW_SCHEME without COOKIE_SECURE |
| T-02-02-02 | Denial of service | Zero/odd durations panic tickers or break probes (WR-08) | mitigate | validate() enforces positivity and ordering; tests per variable |
| T-02-02-03 | Information disclosure | Private keys in env vars or git | mitigate | Only `*_FILE` paths in config; keys generated into git-ignored deploy/.secrets with chmod 600, mounted read-only; never printed |
| T-02-02-04 | Tampering | Malformed allowlist entries silently skipped (WR-09) | mitigate | Format checks for ALLOWED_TEAMS, CREATOR_TEAMS, ALLOWED_REPOS, ENVIRONMENTS_REPO fail startup |
| T-02-02-05 | Tampering | Drift between label keys in Go and in shell/YAML consumers | mitigate | Generated env file under //:check_gen; widened grep gate |
</threat_model>
