## Phase Goal

**As an** SRE, **I want to** create a preview environment from a branch, PR or ref with one dashboard action, **so that** it comes up isolated, resource-limited and emitting telemetry, with the whole creation visible as one trace.

<objective>
The cluster side of the phase: a local kind cluster managed by Bazel targets (D-01), Traefik v3 as the preview gateway at the same `<env-id>.preview.localhost` hostnames with ID-generated `pv-` namespaces (D-03 naming kept) and an entrypoint-level ForwardAuth chain (D-20 replacing ingress-nginx), the fenced provisioner plus per-run deployer token (D-21 refining D-02), the platform-owned namespace baseline (GRD-01, GRD-04), the environments-repo content (thin workflow + provision.sh; D-14), and `kind_verify`, which exercises provision.sh and the gate on real kind without GitHub. The runner registration and publish commands plus README runbook are plan 02-17.

Tool versions come from deploy/kind/versions.env (approved in 02-01). Local kind is v0.29.0 and Helm 3.18.4: `kind.sh tools` installs pinned, checksum-verified binaries into `.tools/bin`, and every command version-checks and prints an install hint on mismatch. Never touch the unrelated exited container named spike-bb. Never call bazel inside kind.sh.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workflow inputs → runner shell | Inputs originate from the platform but cross GitHub |
| Runner host → kind API server | Provisioner credential on the developer machine |
| PR-controlled image → namespace | Untrusted code runs in the preview |
| Preview hosts → Traefik → API ForwardAuth | Every preview request crosses the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13-01 | Elevation of privilege | Self-hosted runner runs untrusted workflow code | mitigate | Private repo, workflow_dispatch only, no fork triggers, admins-only workflow edits, ephemeral runner (02-17), no secrets, pinned checkout SHA |
| T-02-13-02 | Tampering | Workflow input injection | mitigate | Inputs only via env:, provision.sh regex validation before any cluster call, sh_test with injection strings |
| T-02-13-03 | Elevation of privilege | Provisioner escalation / cross-namespace access | mitigate | ClusterRole with bind and token resourceNames, VAPs on name and managed label, kind_verify denial checks |
| T-02-13-04 | Elevation of privilege | Deployer weakens guardrails | mitigate | Deployer has no rbac/namespace/quota/netpol write; 15-minute token discarded after the run |
| T-02-13-05 | Tampering | Namespace-name injection | mitigate | Server-generated ids, regex in provision.sh, VAP name pattern |
| T-02-13-06 | Elevation of privilege | Template bypasses auth | mitigate | Entrypoint-level middleware chain; ingress host VAP |
| T-02-13-07 | Denial of service / lateral movement | PR code in preview | mitigate | Quota, LimitRange, default-deny NetworkPolicy, PSA baseline, no SA token automount |
| T-02-13-08 | Information disclosure | Cluster credential in GitHub | mitigate | Provisioner kubeconfig only in deploy/.secrets (chmod 600, git-ignored); no GitHub secret, no cluster-admin kubeconfig |
| T-02-13-09 | Information disclosure | Tickets in Traefik access logs | mitigate | Access logs disabled |
| T-02-SC | Tampering | kind/helm binaries, images, chart | mitigate | Checksums and digests from versions.env (approved 02-01); kind.sh tools refuses mismatches |
