## Phase Goal

**As an** SRE, **I want to** sign in with GitHub to a running dashboard and find the platform's own traces, metrics, and logs in Grafana, **so that** the platform is observable from the moment it exists.

<objective>
Complete the walking skeleton (see SKELETON.md). An SRE runs one command, signs in through the dashboard with GitHub (fake GitHub in dev/e2e), sees their identity in the app shell on the Telemetry status page, and signs out. That page load is one trace across dashboard, API, and worker, findable in Tempo, with dashboard metrics and logs in Prometheus and Loki.

Covers AUTH-01 SC1 (sign in, sign out), OBS-01 SC2 (one page load + API call -> trace, metric, logs for all three components), D-07 (generated typed client), D-10 (browser trace linked to the API trace), D-12 (web joins the one-command stack), and D-13 (status page, initial form: heading, Grafana link, build info). Plan 01-06 adds the 10-service table and error and empty states. Plan 01-07 adds the denied page content, the user menu, theming controls, and sliding-session behavior.

Output: Playwright e2e specs, authenticated verify helpers, the SPA router, API client, login page, app shell, initial status page, the Compose `web` service, and session protection on `/api/status`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> nginx -> api | Session cookie and traceparent cross into the API |
| URL query params -> SPA | `login`, `reason`, and `next` are attacker-controllable |
| verify scripts -> fake GitHub | Test-only automated login |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-28 | Information disclosure | GET /api/status | mitigate | Security `session` on get-status; RequireSession returns 401 (verified by curl in Task 3) |
| T-01-29 | Tampering | `login` query param on /denied | mitigate | Rendered as React text only (no dangerouslySetInnerHTML; grep gate in 01-07); orgs come from /api/auth/config, not the URL |
| T-01-30 | Tampering | `next` param from the login page | mitigate | Client passes encodeURIComponent(next); server enforces SafeNext (01-04) |
| T-01-31 | Spoofing | Session cookie exposure to JS | mitigate | Cookie is HttpOnly; the SPA never reads it; identity comes only from /api/me |
| T-01-32 | Information disclosure | traceparent to third parties | mitigate | FetchInstrumentation `propagateTraceHeaderCorsUrls: []` keeps traceparent same-origin only; the Grafana link is a plain navigation |
| T-01-33 | Elevation of privilege | Reverse tabnabbing via the Grafana link | mitigate | `rel="noopener noreferrer"` on target=_blank |
</threat_model>
