## Phase Goal

**As an** SRE, **I want to** sign in with GitHub to a running dashboard and find the platform's own traces, metrics, and logs in Grafana, **so that** the platform is observable from the moment it exists.

<objective>
Walking-skeleton telemetry spike (Wave 0 smoke spike). After this plan, an SRE runs `make up` from a fresh checkout, calls `GET /api/status`, and finds one trace, one related metric, and one correlated log for `ephematool-api` in Tempo, Prometheus, and Loki, with Grafana provisioned to navigate between them.

Purpose: Prove the riskiest integration (Collector -> Tempo/Loki/Prometheus -> Grafana correlation) before anything is built on it. This resolves research assumptions A4 (last-signal query), A5 (data-plane half: `trace_id` lands in Loki structured metadata and the derived-field datasource provisions), A6 (Tempo 2.10.8 single-binary config, D-16), and A13 (Collector 0.162 self-metrics `readers` syntax), and it confirms the Prometheus-translated metric names (Pitfall 7).

Implements D-05 (Go), D-06 (Postgres + Redis in the stack; asynq producer), D-07 (Huma code-first OpenAPI), D-08 (research-derived Go stack), D-11 (LGTM + one Collector gateway), D-12 (one Compose command), D-16 (Tempo 2.10.8).

Output: Compose stack, Collector/backend configs, Go API binary with telemetry bootstrap, route-accurate spans, `GET /api/status` (build info + Grafana URL; the `services` list is filled by the prober in plan 01-06), asynq ping producer, verification harness, Makefile, and spike findings recorded in `internal/telemetry/promql.go` and the SUMMARY.
</objective>
