## Phase Goal

**As an** SRE, **I want to** sign in with GitHub to a running dashboard and find the platform's own traces, metrics, and logs in Grafana, **so that** the platform is observable from the moment it exists.

<objective>
Complete the sign-in experience on top of the skeleton (AUTH-01 SC1).
- D-03: sliding 7-day sessions that survive browser restarts, plus sign-out from the user menu.
- D-14: a 30-day absolute cap.
- D-04: a clear denied page, backed by a logged denial event.
- Session-expired and sign-in-failed messages.
- The UI-SPEC user menu with the Light/Dark/System theme switch.

Purpose: plan 01-04 configured the session timeouts, but scs only extends a session when it is modified (Pitfall 1). This plan adds the touch that makes "stay signed in while active" true, and proves it with tests.

Output: the sliding-touch middleware and TestSession suite, the denied/login/user-menu/theme UI, extended Playwright auth tests, and the `auth-denied` verify subcommand.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query (`reason`, `login`) -> SPA | Attacker-controlled display input |
| browser cookie -> RequireSession | Every secured request can extend the session |
| localStorage -> theme | Client-only preference |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-40 | Elevation of privilege | Sliding session renews forever | mitigate | scs absolute `Lifetime` 720h (D-14) caps any session regardless of activity (TestSessionAbsoluteLifetime) |
| T-01-41 | Denial of service | Redis write amplification from touches | mitigate | Touch at most once per `SESSION_TOUCH_INTERVAL` (5m) (TestSessionNoTouchWithinInterval) |
| T-01-42 | Tampering | Reflected content via `reason` / `login` | mitigate | `reason` maps to fixed copy only (unknown values render nothing); `login` is rendered as React text; grep gate forbids dangerouslySetInnerHTML; Vitest asserts literal rendering |
| T-01-43 | Spoofing | Social engineering via a crafted /denied link | accept | Page only states access was denied and links to /login; it performs no action and reveals only public allowlist org names |
| T-01-44 | Repudiation | Denials untraceable | mitigate | `auth.denied` Warn log reaches Loki (auth-denied verify subcommand) |
| T-01-45 | Tampering | Logout CSRF from the menu | mitigate | Logout is POST behind CrossOriginProtection and a SameSite=Lax cookie (01-04) |
</threat_model>
