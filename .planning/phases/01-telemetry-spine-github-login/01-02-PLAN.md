**As an** SRE, **I want to** sign in with GitHub to a running dashboard and find the platform's own traces, metrics, and logs in Grafana, **so that** the platform is observable from the moment it exists.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> nginx /otlp | Unauthenticated, internet-style input reaches the collector |
| browser -> nginx /api | Cookie-bearing requests proxied to the API |
| browser localStorage | Theme preference only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Denial of service | nginx /otlp proxy | mitigate | POST-only via `limit_except`, path regex allowlist (traces/logs/metrics only), `client_max_body_size 1m`, `limit_req zone=otlp rate=20r/s burst=20`; collector memory_limiter (01-01) |
| T-01-09 | Information disclosure | nginx /otlp proxy | mitigate | `proxy_set_header Cookie ""` and `Authorization ""` so session cookies never reach the collector |
| T-01-10 | Tampering | Browser telemetry poisoning | accept | Browser spans are tagged `service.name=ephematool-dashboard` and are untrusted by design; local dev stack only in Phase 1 |
| T-01-11 | Information disclosure | Browser metrics/logs | mitigate | Metric attributes limited to route template and outcome; no login, URL, or token in attributes |
| T-01-12 | Tampering | localStorage theme value | mitigate | `readThemeChoice` accepts only "light"/"dark"/"system" (tested); any other value falls back to "system" |
| T-01-SC | Tampering | npm installs | mitigate | Task 1 blocking-human gate for [SUS] vitest; exact pins in package.json and a committed package-lock.json; `npm ci` in the Dockerfile |
</threat_model>
