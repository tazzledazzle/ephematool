2. Call api_get /api/status and /api/me and collect their trace ids. Also collect the login callback trace by running a fresh fake login and reading X-Trace-Id from the callback response headers.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| api/browser telemetry -> Tempo/Loki | Possible leakage of secrets into stored telemetry |
| host -> Grafana | Anonymous Admin on the dev stack |
| docs -> operators | Insecure dev defaults copied to production |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-46 | Information disclosure | Secrets in telemetry | mitigate | `redaction` subcommand greps Tempo traces and Loki logs from a real login + status flow for cookie values, `Bearer `, `access_token`, client secret, and header attribute keys; it runs in `make verify` |
| T-01-47 | Elevation of privilege | Anonymous Grafana Admin copied to production | mitigate | README "Security notes (dev stack only)" plus DEV-ONLY comments in compose; ports bound to 127.0.0.1 |
| T-01-48 | Spoofing | Session cookie over plain HTTP outside localhost | mitigate | README and .env.example require `COOKIE_SECURE=true` for any non-localhost deployment |
| T-01-49 | Tampering | Grafana dashboard edits lost or diverging | accept | Provisioned dashboard is the source of truth (`disableDeletion: true`); local edits are dev-only |
| T-01-50 | Information disclosure | fresh.sh temp clone | accept | Clone contains only committed files (no .env); removed in a trap |
</threat_model>
