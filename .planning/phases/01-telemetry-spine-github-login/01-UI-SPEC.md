# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Screens in scope: (1) Sign-in, (2) Access denied, (3) Signed-in app shell, (4) Telemetry status page. Sources: CONTEXT D-01..D-04, D-07, D-10, D-13; Tailwind + shadcn/ui from research STACK.md (frontend rows not superseded by D-05..D-07). Unconfirmed defaults are listed under Decisions and Remaining Assumptions.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (CLI) on Tailwind CSS 4 (user-confirmed). Not yet initialized: greenfield repo, no `components.json`. Wave 0 of the SPA plan runs `npx shadcn init` with the default preset (base color neutral, CSS variables on). |
| Preset | not applicable until user supplies a preset string; default init is used |
| Component library | radix (user-confirmed) |
| Icon library | lucide-react |
| Font | Inter via system fallback stack: `Inter, ui-sans-serif, system-ui, sans-serif`; mono `ui-monospace, SFMono-Regular, Menlo, monospace` for build SHA, trace IDs, versions |

Theme: light and dark both ship in Phase 1 (user decision). Colors are CSS variables on `:root` (light) and `.dark` (dark) using the shadcn class strategy; components never hard-code hex values. Default theme is System (follows `prefers-color-scheme`); the user's explicit choice persists in `localStorage` key `ephematool-theme`. An inline script in `index.html` sets the `dark` class before first paint to prevent a flash of the wrong theme.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing, label-to-value gap |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, card-to-card gap |
| xl | 32px | Layout gaps, auth card inner padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top spacing (auth pages) |

Exceptions: interactive controls (buttons, sign-out menu trigger, Grafana link button) have a 44px minimum touch height (h-11). App header height is 56px (a multiple of 4, fixed).

## Typography

Four sizes, two weights (400 regular, 600 semibold). No other sizes or weights in this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Usage: Display = auth page titles ("Sign in to Ephematool", "Access denied"). Heading = page title on status page and card titles. Label = badge text, table column heads, field captions. Body = everything else. Mono-spaced values (SHA, trace ID) use Body size at weight 400.

## Screens and Layout

### 1. Sign-in (`/login`)
- Centered card, max-width 400px, top offset 3xl, padding xl, on dominant background.
- Contents top to bottom: product name (Label), Display title, Body subline, full-width primary button with GitHub mark icon.
- No form fields. Button navigates to the API's OAuth start endpoint (full page navigation, not fetch).
- If already signed in, redirect to `/` immediately.
- Focal point: the Display title first, then the full-width primary button (largest and only accent-filled element on the page).
- Theme: auth pages follow the stored or system preference; they have no toggle.

### 2. Access denied (`/denied`)
- Same card shell as sign-in. Display title, Body explanation naming the required org(s)/team(s) (values from API config, rendered as mono inline code), signed-in GitHub username shown as context, and a secondary button "Try a different account" that returns to `/login`.
- Page is public (user was signed out per D-04). It reads the denial reason and required org list from the API's denial response / query param `reason=org_membership`; it must not depend on a session.
- Role `alert` is not used (static page); heading receives focus on load.
- Focal point: the Display title first, then the "Try a different account" button. The org list in mono is the key information inside the body.

### 3. App shell (authenticated layout)
- Fixed header, 56px, secondary background, bottom border. Left: product name "Ephematool" in Heading role (20px/600).
- Nav: single item "Telemetry" (active-route indicator in accent). Later phases add items; shell renders a nav list, not hard-coded single link.
- Right: user menu (avatar 32px, GitHub login, role badge `Admin` or `Viewer`) opening a menu containing, in order: a "Theme" radio group (Light, Dark, System; selected item shows a check icon; System is the default and is selected when no choice is stored) and a separator followed by "Sign out". Sign out calls the API, clears session, redirects to `/login`. Theme change applies immediately, with no confirmation, and the menu stays open so the effect is visible. The avatar trigger is icon-only: `aria-label="Open user menu for {login}"` and a tooltip "Account menu".
- Content area: max-width 1024px, centered, padding lg horizontally, 2xl top.
- Unauthenticated access to any shell route redirects to `/login`; session expiry mid-use (401) redirects to `/login` with no extra toast.

### 4. Telemetry status page (`/`)
Vertical stack, gap lg:
1. Page header row: Heading "Telemetry status", right-aligned "Open in Grafana" accent link button (external-link icon, opens new tab, `rel="noopener noreferrer"`). Link target is provided by the API (configured Grafana base URL), not hard-coded in the SPA.
2. Card "Signed in as": avatar, GitHub login, role badge, org(s) that granted access.
3. Card "Build": definition list of version, commit SHA (mono, first 7 chars, full value in `title`), build time (ISO date plus relative), for API and dashboard in two columns (stack on <768px).
4. Card "Service telemetry": table with columns Service, Status, Last signal. Rows are grouped under full-width group header rows (Label role, `role="rowgroup"` semantics with a visually distinct secondary background): **Platform** (API, Worker, Dashboard); **Data** (Postgres, Redis); **Telemetry pipeline** (OTel Collector); **Observability backends** (Tempo, Loki, Prometheus, Grafana). Group order is fixed as listed; rows within a group are in the order listed. Status uses the health badge above. Last signal is a relative time ("12s ago") with absolute timestamp in `title`. Per-service signals shown as three tiny labeled indicators Traces / Metrics / Logs are NOT in scope; one overall status per service.
- Data: one `GET /api/status` call via the generated client, polled every 15s in place with TanStack Query (user-confirmed). No websockets.
- Focal point: the Heading "Telemetry status" first, then the health badges in the service table (badges are the only colored elements besides the Grafana button, so a Degraded or Down row stands out immediately).

Responsive: single column below 768px; table becomes stacked rows (service name over status and time).

## Interaction and Loading Contract (trace-aware, D-10)

- The SPA initializes browser OTel before first render and propagates `traceparent` on every generated-client request, so one page load is one trace linked to API spans. UI must not obscure that trace:
  - No artificial minimum-delay spinners, no debounce on initial fetches, no client-side request batching or caching layer that suppresses the network call on mount.
  - Each data region (user, status) loads independently and renders its own skeleton immediately (skeleton blocks matching final dimensions, no layout shift). No full-page blocking spinner after the shell is mounted.
  - No silent automatic retries in UI code. Failed requests show the error state once; the user presses "Retry Loading Status", which issues a new, separately traced request. (Library-level transport retries are disabled for GET status calls.)
  - Polling refetches update in place without skeletons; a stale-data indicator ("Updated 40s ago") appears only if a poll fails.
  - Error states display the trace ID (mono, Body size) taken from the response `traceparent`/`X-Trace-Id` header, with an icon-only copy button (`aria-label="Copy trace ID"`, tooltip "Copy trace ID", changing to "Trace ID copied" for 2 seconds after activation, announced via `aria-live="polite"`), so an SRE can paste it into Grafana. Tooltips on icon-only controls appear on hover and on keyboard focus.
- Auth bootstrap: the shell calls `GET /api/me` once; while pending, render the header skeleton and content skeleton (no flash of login page).
- Focus management: route change moves focus to the page Heading (`tabindex=-1`). Menu and buttons are keyboard operable; visible focus ring in accent.
- Reduced motion: respect `prefers-reduced-motion`; skeleton uses a static tint in that mode. Theme switching does not animate.

## Decisions and Remaining Assumptions

User-confirmed (this revision):
1. Tailwind 4 + shadcn/ui, Radix, lucide.
2. Light and dark themes from the start; default System; toggle (Light / Dark / System) in the user menu.
3. Status page keeps 15s in-place polling; service list includes the LGTM backends, grouped Platform / Data / Telemetry pipeline / Observability backends.

Still assumed (not yet confirmed):
1. Default shadcn preset (no preset string supplied); `components.json` not yet created (initialize in Wave 0).
2. Inter font stack; accent blue (#2563EB light, #60A5FA dark).
3. A separate warning color is permitted for the "Degraded" badge only, in addition to destructive.
4. Role badge (Admin/Viewer) is shown in the header and status page.
5. Denied page is public and reads required orgs and username from the API denial response or query params; transport is a planner/API decision.
6. Error states surface the trace ID; this requires the API to return a trace ID header.
7. Single-nav-item shell designed to extend in Phase 2.
8. Header product name uses the 20px/600 Heading role to stay within the 4-size, 2-weight set.
9. The status API must report all 10 services (API, Worker, Dashboard, Postgres, Redis, OTel Collector, Tempo, Loki, Prometheus, Grafana); how health is probed is a backend decision.
