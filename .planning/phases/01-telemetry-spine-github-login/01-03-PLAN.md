## Phase Goal

**As an** SRE, **I want to** sign in with GitHub to a running dashboard and find the platform's own traces, metrics, and logs in Grafana, **so that** the platform is observable from the moment it exists.

<objective>
After this plan, an SRE calls `GET /api/status` and sees one trace that spans the API and the worker in Tempo, with correlated worker logs in Loki and worker task metrics in Prometheus (OBS-01 for the worker, D-06 Redis queue). This plan also encodes the D-09 label and attribute prefixes once, in a generated constants module shared by Go and the SPA.

Purpose: the worker is the third telemetry-emitting component. Phase 2 provisioning and reaper jobs reuse this exact propagation wiring.

Output: `cmd/worker`, asynq consumer tracing middleware, the heartbeat scheduler, the Compose `worker` service, the `worker` verify subcommand, and the conventions generator with Go and TS output plus a grep gate.

Constraint: this plan adds no Go module dependencies. asynq, go-redis, redisotel, otel, and testify were added in 01-01. Do not run a `go get` that changes go.mod; plan 01-04 owns go.mod in this wave.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| api -> redis -> worker | Task headers and payload cross a process boundary through Redis |
| worker -> collector | Worker telemetry export |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Tampering | asynq task Headers | accept | Redis is not published to the host and is reachable only on the Compose network; headers carry only W3C traceparent/baggage; Phase 1 tasks carry no payload and perform no privileged action |
| T-01-14 | Denial of service | Telemetry flood from asynq polling | mitigate | asynq server/scheduler use uninstrumented `asynq.RedisClientOpt` (grep gate on server.go); only the app client is instrumented |
| T-01-15 | Denial of service | Metric cardinality | mitigate | Task metrics carry only `task.type` and `outcome` (asserted in TestTaskMetrics); no task IDs on metrics |
| T-01-16 | Repudiation | Heartbeat spoofing | accept | Heartbeat only drives a status display; Redis is network-private |
| T-01-17 | Tampering | Conventions drift (D-09) | mitigate | `make check-gen` diff gate plus `conventions` grep gate forbid hand-written prefixes |
</threat_model>
