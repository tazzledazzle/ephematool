  internal/status:
    type Service struct{ ID, Name, Group string }   // fixed table Services (order is the contract)
    Services = [ {api, API, platform}, {worker, Worker, platform}, {dashboard, Dashboard, platform}, {postgres, Postgres, data}, {redis, Redis, data}, {otel-collector, OTel Collector, pipeline}, {tempo, Tempo, backends}, {loki, Loki, backends}, {prometheus, Prometheus, backends}, {grafana, Grafana, backends} ]
    type Result struct{ ID string; Status string; LastSignalAt *time.Time; Detail string }
    type Checks struct{ Postgres func(ctx) error; Redis func(ctx) error; HeartbeatAt func(ctx) (time.Time, error); HTTP map[string]string /*id->url*/; LastSignal func(ctx) (map[string]time.Time /*service_name->ts*/, error); Now func() time.Time }
    func NewProber(c Checks, interval, timeout time.Duration, meter metric.Meter) *Prober
    func (p *Prober) Run(ctx context.Context)          // probes immediately, then every interval; one goroutine; plain http.Client, no otelhttp
    func (p *Prober) Snapshot() (generatedAt time.Time, results []Result)   // always 10 entries in Services order; "unknown" before the first probe
  Status mapping (RESEARCH Pattern 5):
    probe failed -> down
    api: healthy if the handler runs; plus last signal for ephematool-api
    worker: heartbeat older than 45s or missing -> down; last signal from Prometheus for ephematool-worker
    dashboard: web /healthz fails -> down; no ephematool-dashboard signal for >60s -> degraded
    platform row with probe ok but signal older than 60s -> degraded; Prometheus query error -> unknown (platform rows only)
    data/pipeline/backends: lastSignalAt = last successful probe time
  Prometheus service_name -> id: ephematool-api->api, ephematool-worker->worker, ephematool-dashboard->dashboard
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| api prober -> internal services | Outbound HTTP to fixed, config-defined internal URLs |
| api -> browser (/api/status) | Health data shown to signed-in users |
| api -> Prometheus query | PromQL from a constant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-34 | Information disclosure | /api/status | mitigate | Requires a session (01-05); returns service ids, statuses, timestamps, and a short detail (HTTP status or "timeout") only; no internal URLs, hostnames, or error stack text |
| T-01-35 | Denial of service | Request-time fan-out | mitigate | Handler serves the cached Snapshot(); probes run in one background goroutine with a 2s timeout (TestProbeTimeout) |
| T-01-36 | Server-side request forgery | Prober targets | mitigate | Target URLs come only from server config; no request input influences them |
| T-01-37 | Tampering | PromQL injection | mitigate | Query is the constant `telemetry.LastSignalQuery`, URL-escaped; no user input |
| T-01-38 | Denial of service | Telemetry noise from probes | mitigate | Uninstrumented client (grep gate); probe results exported as metrics with a bounded `service` attribute (10 values) |
| T-01-39 | Information disclosure | Trace id on the error UI | accept | The trace id is a random correlation id for the user's own request; useful for SRE debugging per UI-SPEC |
</threat_model>
